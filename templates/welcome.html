Quick check

Show the service info:

curl -u '{{ tes_user }}:{{ tes_password }}' {{ tes_url }}/v1/service-info

Submit a test task (it prints the task id):

curl -u '{{ tes_user }}:{{ tes_password }}' -H 'Content-Type: application/json' \
  -d '{"name": "hello", "executors": [{"image": "alpine:3.20", "command": ["echo", "hello from TES"]}]}' \
  {{ tes_url }}/v1/tasks

Check on it, replacing <id> with the id from the previous command:

curl -u '{{ tes_user }}:{{ tes_password }}' '{{ tes_url }}/v1/tasks/<id>?view=FULL'
Note: every executor in a task must name a container image. Images are pulled from Docker Hub (or another registry) and run with Apptainer (CONTAINER_TYPE={{ tesp_container_type | default('singularity', true) }}).

A task's resources.cpu_cores and resources.ram_gb are passed to SLURM (--cpus-per-task, --mem): a task waits until that much is free on this node, and fails if it asks for more than the node has. SLURM reserves the resources but doesn't cap what a running task uses.

Long tasks are fine: the service waits until a task's job finishes, however long it queues or runs. {% if tesp_max_wait_seconds | default(0) | int > 0 %} On this workspace a task whose job hasn't finished {{ tesp_max_wait_seconds | int }} seconds after submission, queue time included, is canceled and ends in SYSTEM_ERROR. {% endif %} A task with S3 outputs must finish within {{ tesp_s3_output_presign_expiry_seconds | default(86400, true) | int }} seconds, or its uploads fail. Tasks that are queued or running when the service restarts (for example when the workspace is redeployed) are lost: they never get their logs or final state.
